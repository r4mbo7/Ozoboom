## Règles

- Une issue, une branche `issue-<numéro>-<slug>`, une pull request qui la ferme, fusion quand la CI est verte. Un agent ne prend qu'une issue `ready`.
- Les couches ne se touchent pas : `sim` n'importe rien d'au-dessus, `render`, `input`, `audio` et `ui` ne s'importent pas entre elles, `app` assemble. ESLint le vérifie.
- Un contrat partagé se change par une petite pull request additive à part, annoncée dans l'issue concernée avant fusion.
- Chaque couche se développe sans la sim : page `dev/<couche>.html` sur un état fixture. La sim a `src/sim/fixtures.ts`. Le vrai contenu (#4) ne sert qu'à l'assemblage.
- L'ordre des systèmes de la sim est fixé par #1 dans `src/sim/index.ts` ; #2 et #3 y insèrent leurs systèmes aux emplacements nommés, chacun dans ses propres fichiers.
- Quand #1 fusionne : retirer `blocked` et poser `ready` sur #2 et #3. Quand tout le reste a fusionné : sur #10.
- La page d'attente de `src/main.ts` reste jusqu'à #10. `main` reste déployable entre deux fusions.

## Lancer un agent sur une issue

Contexte frais, dépôt propre (clone ou worktree), puis :

> Prends l'issue #N du dépôt r4mbo7/Ozoboom. Lis `AGENTS.md`, puis les documents que l'issue indique, puis l'issue. Implémente-la entièrement, `pnpm check` vert, et ouvre une pull request qui la ferme, avec les preuves demandées par ses critères d'acceptation.
