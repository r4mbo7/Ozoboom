Au 2026-10-05, tout est fusionné sauf l'assemblage : #149 apporte le banc à quatre joueurs (`?dev=bench&players=4`), les mesures sur machine locale, les captures et le README. Le jalon reste ouvert : ce qui demande de vraies machines revient à Constantin.

Mesuré en local (i9-12900HK, RTX 3050 Ti, Chromium affiché) : quatre joueurs et 300 bad vibes à 60 images par seconde, 0,93 ms de sim, 1,39 ms de rendu, 0,21 ms d'interface par image ; l'invité à quatre échange 20,3 ko/s (envoie 4,7, reçoit 15,5), à la limite des 20 ko/s de R24 ; transport prêt en moins de 200 ms, aller-retour 1 ms.

Reste à Constantin : une partie à distance sur deux réseaux (dix connexions, un set entier, divergences), une partie à deux manettes sur un écran, les 60 images par seconde à quatre sur son portable sans carte dédiée, puis les critères de réussite du document d'exigences ; ensuite fermer le jalon.

Quatre agents dès maintenant (vague 1), dix dès que les contrats sont fusionnés, puis les trois de la vague 3. Les lettres sont les clés des issues : C contrat, S sim, N net, I input, R render, U ui, A audio, P app.

## Règles

- Celles de [v0.1.md](v0.1.md) : une issue, une branche `issue-<numéro>-<slug>`, une pull request qui la ferme, fusion quand la CI est verte ; les couches ne se touchent pas ; un contrat partagé change par une petite pull request additive à part.
- Les contrats de la vague 1 posent des types et des écrans minimaux, inertes : `main` reste jouable seul tant que le salon n'est pas assemblé.
- `src/net/` est du TypeScript pur, testé sur les transports en mémoire de #133 ; `peerjs` ne s'importe que dans `src/net/peerjs.ts`, et seulement au premier salon en ligne.
- L'interface ne connaît pas le réseau : elle rend un `LobbyModel` et renvoie des gestes ; `app` fait le lien.
- Les nombres (vie, dégâts, échelle par joueur) sont des points de départ dans `src/data/`, réglés par #137 sans écran, jamais dans la logique.
- Quand une issue de contrat fusionne : retirer `blocked` et poser `ready` sur les issues qu'elle débloque (liste dans son texte). Quand toutes les autres ont fusionné : sur #149.
- Les mesures qui demandent une vraie machine (deux réseaux, manettes, images par seconde) restent à Constantin et sont listées dans #149.

## Lancer un agent sur une issue

Contexte frais, dépôt propre (clone ou worktree), puis :

> Prends l'issue #N du dépôt r4mbo7/Ozoboom. Lis `AGENTS.md`, puis les documents que l'issue indique, puis l'issue. Implémente-la entièrement, `pnpm check` vert, et ouvre une pull request qui la ferme, avec les preuves demandées par ses critères d'acceptation.

Plusieurs agents sur la même machine : un worktree chacun, qui lance ses tests navigateur sur ses propres ports, cinq au plus à la fois.
